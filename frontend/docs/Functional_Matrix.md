# DCFMS — Module-by-Module Functional Matrix

**Legend / assumptions**
- **Roles** are RBAC personas scoped by administrative level (Federal / Regional / Zonal / Woreda / Kebele).
- **Analysis** = automated validation, computation, or rule evaluation performed by the system (not a human analyst).
- **Reports** = generated, exportable artifacts (PDF/CSV/dashboard export).
- All screens are **bilingual (Amharic/English)**, **WCAG 2.1 AA**, and **RBAC-scoped**; "offline" means capture-and-sync.

## Cross-cutting constraints (apply to all modules)

| Constraint | Requirement |
|---|---|
| **Access model** | RBAC with least privilege, Zero Trust, MFA for admins; scope by Federal/Regional/Zonal/Woreda/Kebele |
| **Connectivity** | Offline capture with incremental sync; text-first UI for low bandwidth |
| **Language & accessibility** | Amharic + English; WCAG 2.1 Level AA; guided onboarding for low digital literacy |
| **Auditability** | Every create/update/approve/pay action immutably logged with user, timestamp, IP/device, outcome |
| **Data protection** | Consent-gated sharing; PII masking in analytics; compliance with Proclamation 1321/2023 and 1205/2020 |
| **Performance** | Web 80% <3s / 95% <5s; mobile 80% <2s on 3G; batch/report jobs async with notification |
